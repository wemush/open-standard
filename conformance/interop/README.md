# Interop vectors: cross-implementation round trips

The other vector files check that an implementation *decrypts* fixtures made by
`generate_vectors.py`. This set checks that labels *generated by real
implementations* decrypt everywhere else. It covers the WOLS 1.3.0 encrypted
URL format (`kdf=pbkdf2` and `kdf=raw`) and field-level encryption.

| File | Contents |
| ---- | -------- |
| [`matrix.json`](./matrix.json) | The case matrix: inputs only. ASCII-only, so non-NFC strings can't be renormalized by an editor. |
| [`corpus/typescript-1.3.0.json`](./corpus/typescript-1.3.0.json) | Labels generated from the matrix by [`@wemush/wols`](https://github.com/wemush/specimen-labels-js) 1.3.0 |
| [`corpus/python-1.3.0.json`](./corpus/python-1.3.0.json) | Labels generated from the matrix by [`wols`](https://github.com/wemush/specimen-labels-py) 1.3.0 |
| [`SHA256SUMS`](./SHA256SUMS) | Checksums for the files above |

The matrix, the corpora and the two reference harnesses
(`tests/interop/harness.py` and `tests/interop/harness.mjs`) are maintained in
[wemush/specimen-labels-py](https://github.com/wemush/specimen-labels-py/tree/main/tests/interop),
and both libraries run them in CI against each other's published release and
`main` branch. The copies here are a snapshot of that set, for third parties.
`conformance/tools/verify_vectors.mjs` decrypts both corpora with its own
implementation of the spec.

The set lives in `conformance/interop/` rather than under `conformance/vectors/`
because the libraries vendor `conformance/vectors/` as a flat directory of
vector files, and these corpora are not vector files in that format.

## What the matrix covers

- **Hostile IDs:** the spec example `wemush:Lab A/plate+3%` (which a generator
  must emit as `Lab%20A%2Fplate%2B3%25`), `?`, `&`, `=`, `#`, `+` versus space,
  literal `%41`-style text, sub-delims, JSON-escape characters, control
  characters, Latin, CJK and supplementary-plane characters, and an NFD ID that
  must not be normalized. Field-level cases put the same IDs into the AAD.
- **Passphrases:** NFD and NFC spellings that must derive the same key, U+212B,
  Hangul jamo, a ligature that NFKC would change, leading and trailing spaces
  that must not be trimmed, and supplementary-plane characters.
- **Iterations:** the minimum (100,000) and the generator's default (600,000).
- **`sig`:** an optional signature parameter that a decoder must return unchanged.

## Case format

Each case names a document (`specimens[specimen]` with `id` set to
`specimenId`), a `form` (`url` or `fields`) and a `kdf`:

- `pbkdf2`: encrypt with `passphrase` and `iterations` (omitted means the
  generator's default; `expectIterations` is what the label must carry). Every
  entry of `decryptPassphrases` must decrypt; every entry of `rejectPassphrases`
  must fail authentication.
- `raw`: `key` is the 32-byte key, base64url without padding.
- `url` cases may carry `sig` (attach it as the `sig` parameter) and
  `expectPathSegment` (the exact percent-encoded ID path segment).
- `fields` cases list the `fields` to encrypt with field-level encryption.

A decrypted document must equal the matrix document exactly (compare parsed
JSON, not bytes, since member order may differ).

A corpus is `{"corpusVersion": 1, "matrixSha256": <SHA-256 of matrix.json>,
"generator": {"implementation", "language", "version"}, "cases": {<case id>:
{"url": ...} | {"document": ...}}}`.

`expectedFailures` lists known divergences between the two libraries, with a
reason and a reference. At 1.3.0 the only entry is `strain.generation` as a JSON
number: `wols` emits it, and `@wemush/wols` rejects it after decryption because
the specification types `generation` as a string. It isn't an encryption
divergence, and implementations that don't validate the decrypted document
pass those cases.

## Joining the matrix

To show that a new implementation interoperates:

1. **Decode:** decrypt every case of both corpora here with your decoder, using
   the matrix secrets, and compare with the matrix document. Check that `sig` is
   preserved and that `rejectPassphrases` fail.
2. **Generate:** generate a corpus from `matrix.json` with your encoder (fresh
   random IVs and salts, as in production), then verify it with both reference
   harnesses:

   ```bash
   python harness.py verify matrix.json your-corpus.json
   node harness.mjs verify matrix.json your-corpus.json
   ```

   The harnesses also check your output against the 1.3.0 wire rules:
   path-segment encoding, canonical unpadded base64url, IV and salt lengths,
   decimal iterations, and a fresh IV per field.
3. **Contribute** (optional): open a pull request that adds your corpus as
   `corpus/<language>-<version>.json` and updates `SHA256SUMS`. Once it lands,
   the libraries can verify it too.
